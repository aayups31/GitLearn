# Included AI deployment

OutClass accounts use Supabase email codes. The included AI service runs alongside the landing page on Vercel; users need an OutClass account, not an OpenAI key. The desktop app never contains the service provider secret. The connected environment currently uses Stripe test mode and Resend's test sender, so it is an owner-testing environment, not a public paid offering.

## Connect infrastructure

1. Create a Supabase project. Configure both **Confirm sign up** and **Magic link or OTP** with [the numeric-code template](email/sign-in.html), subject `Your OutClass sign-in code`. Configure SMTP and account abuse controls. Resend's test sender only delivers to the account owner; a verified sender domain is required for other learners. The gateway validates each account token with Supabase's user endpoint. Do not expose a service-role key to clients.
2. Apply the versioned SQL in `supabase/migrations` once with administrative access. Configure `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` (legacy `SUPABASE_ANON_KEY` also works), and a restricted runtime `DATABASE_URL`. The server verifies the existing schema on startup; it never runs migrations or grants privileges. The private schema has RLS and narrowly scoped internal server-role permissions; anonymous and authenticated browser roles have no access. Use verified TLS with `DATABASE_CA_CERT` when required, and a direct or session-pooled connection. Transaction-mode poolers cannot preserve billing's session advisory locks. The provisioning helper creates a separate restricted login and retains the owner URI only in ignored local storage.
3. Create a separate production OpenAI project/service key. Configure it only on the host, plus the model and your provider spend limit. See https://developers.openai.com/api/docs/guides/production-best-practices . No provider secret is returned to users. Prompt contents are not stored by the service; Responses uses `store:false`.
4. Choose allowances and commercial pricing. Defaults are 20 free and 600 paid bounded requests per calendar month, not promised retail pricing. Each structured answer consumes one request; failed inference refunds it. Context/output limits constrain each call. Atomic PostgreSQL account-month reservations prevent concurrent overspending. A separate atomic global monthly attempt allowance limits total service exposure, including across accounts. Provider failures refund the learner but remain counted in the global attempt limit. Per-process request/concurrency limits supplement these database bounds. Add host-level abuse protection before public launch.
5. Optional billing: follow the [OutClass billing plan](../../docs/stripe-integration.md). Configure the key, fixed monthly price and webhook signing secret together, plus the dedicated portal configuration ID. Subscribe to the plan's checkout, subscription and invoice events. Existing subscriptions open the portal, including payment recovery. Signed webhooks reconcile current subscriptions and paid invoices using the database customer mapping; redirects never grant access. Duplicate upgrade clicks reuse Checkout, and delayed cancellation events cannot revoke a newer purchase. `STRIPE_AUTOMATIC_TAX` stays false until registrations/settings are ready.
6. Follow [Vercel deployment](../../docs/vercel-deployment.md). `api/ai.ts` wraps the shared Express runtime; the database pool is reused and registered with Fluid compute. Upload only the allowlisted service settings using `scripts/upload-ai-environment.mjs`, which passes secret values through CLI stdin. `OUTCLASS_PUBLIC_URL` is the public origin used for payment return pages. `/health` is liveness; `/ready` checks the database. A container is also supported: `docker build -f services/ai/Dockerfile -t outclass-ai .`. Inject secrets through the host, never the image.
7. In OutClass → Settings → Included AI, set that HTTPS service URL, save, enter an email and the verification code, then enable AI guides. Windows uses encrypted account storage. Source-development sessions stay in memory; sign in again after restart.

## Boundaries and operations

The service exposes three purpose-limited answer tasks: teacher, architect and optional checkpoint description. It supplies the role instructions and validates structured output; it is not a general API-key proxy or autonomous coding agent. Filesystem execution, original notebooks, retrieval indexes and checkpoints stay on the learner's computer. Each requested answer sends the relevant bounded context. Local keyword retrieval avoids a paid embedding requirement for included/local AI.

No public sign-in or subscription is advertised until Supabase/Stripe/provider/hosting are configured and a real staging smoke test passes. Unit/integration tests use injected accounts/allowances/model responses and never charge a provider. Before accepting real payments, test the actual configured PostgreSQL service, email delivery, refunds, concurrent reservations, webhook signature rejection, subscription cancellation and Stripe test-mode checkout end to end. Use a reverse proxy/host with explicit trusted forwarding configuration rather than trusting arbitrary forwarded IP headers.

Requests/usage contain account IDs and timestamps, not prompt text. Decide and publish account/usage retention and deletion policy before opening a public service. Notebook deletions and editing clear locally derived history; already transmitted context cannot be recalled from a provider.

## Infrastructure verification

Run `node --import tsx scripts/verify-ai-database.ts` for real PostgreSQL concurrency, refund, lock, retry and role-isolation checks. It cleans only its synthetic fixtures. Run `node --import tsx scripts/verify-ai-runtime.ts` for HTTP readiness, account rejection, billing return pages and raw Stripe signatures without emails/model calls. Set `OUTCLASS_VERIFY_URL` to the configured public origin to repeat the runtime checks against Vercel. `scripts/verify-hosted-billing.ts` tests Stripe-delivered payment/cancellation events against that deployed endpoint and the real database using synthetic test accounts. It cleans its fixtures and never initiates a live charge. Sanitized reports remain in ignored `.local` files.
